# Sprint 20-A 全站极简化与首次使用引导设计

## 1. 目标与边界

Sprint 20-A 不新增大型业务模块，也不重做视觉品牌。目标是让普通企业用户无需理解 GEO、Provider、模型 ID、Base URL 或内部枚举，即可完成第一次真实 AI 搜索检测，并在核心页面始终看懂：

- 当前所在位置与页面用途；
- 系统当前真实状态；
- 已完成的真实工作；
- 唯一且明确的主要下一步；
- 失败原因及可执行的解决办法。

本轮继续复用现有 Project、Provider、AI Search、Growth、Optimization、Automation、Report 与 i18n 架构。禁止 Mock、假进度、固定延迟、虚假评分、虚假 Before/After 和伪造成功记录。

## 2. 已确认的架构方案

采用“共享引导层 + 各页面渐进简化”方案：

1. 首次使用状态全部从现有业务数据库实时推导；
2. 不新增独立 Onboarding 状态表；
3. 建立共享状态服务和统一体验组件；
4. 各核心页面逐步接入共享能力；
5. 技术信息保留，但默认收进“查看技术详情”；
6. 每个核心页面只保留一个视觉权重最高的下一步操作。

不采用集中式巨型向导，因为它会复制业务状态并限制现有模块；不采用各页面独立判断，因为容易出现状态和文案不一致。

## 3. 检测问题与历史结果

### 3.1 `AISearchQuery` 调整

在现有 `AISearchQuery` 上增加最小必要字段：

- `normalizedQuery`：经过首尾去空格、连续空白折叠和大小写归一化后的文本；
- `archivedAt`：问题归档时间，`null` 表示当前启用；
- `updatedAt`：最近保存或重新激活时间。

建立 `projectId + normalizedQuery` 唯一约束，保证并发重复保存不会产生重复记录。迁移时为现有记录补齐标准化文本；若历史数据存在重复问题，保留最早记录，并把其他记录的历史结果安全关联到保留记录后再建立唯一约束。

保存规则：

- 新问题创建一条 `AISearchQuery`；
- 相同标准化文本再次保存时返回原记录；
- 相同问题已归档时重新激活原记录，不创建新记录；
- 保存问题不创建 `AISearchResult`；
- 删除操作采用归档，不删除历史结果。

### 3.2 检测执行

运行检测必须携带现有 `queryId`。服务端再次验证 Query 属于当前用户的 Project，并为该 Query 新增一条 `AISearchResult`：

- 每次运行都新增历史 Result；
- 不覆盖旧 Result；
- 成功时保存真实回答、品牌提及、排名与 Citation；
- 失败时保存 `FAILED`、安全错误码、耗时和尝试次数；
- 失败结果的回答、品牌提及、排名和 Citation 保持为空；
- 不允许客户端提交其他项目的 Query。

现有直接提交问题文本的旧调用保持兼容，但内部先查找或创建标准化 Query，再复用统一执行流程。

## 4. 首次使用状态推导

新增项目级引导汇总服务与只读 API。状态来自真实数据：

1. **创建企业项目**
   - 当前 Project 存在即为已完成。
2. **连接 AI 平台**
   - 官方 Provider 已启用且模型验证可用，或第三方网关存在已验证可用模型，才算已完成；
   - 已配置但测试失败时为需要处理。
3. **添加检测问题**
   - 存在未归档 `AISearchQuery` 即为已完成。
4. **运行第一次检测**
   - Query 存在但无 Result：未开始；
   - 存在 `PENDING` 或 `RUNNING` Result：进行中；
   - 只有失败 Result：需要处理；
   - 存在成功 Result：已完成。
5. **查看结果和优化建议**
   - 存在成功结果及可追溯 Insight、OptimizationTask 或 GrowthAction 时为已完成；
   - 成功检测后尚无建议时，引导查看检测结果。

服务同时返回：

- 五步真实状态；
- 当前主要问题；
- 唯一推荐下一步；
- 对应路由和按钮文案；
- 最近真实完成记录；
- 数据来源标识。

不把引导状态写回数据库。

## 5. 共享体验组件

建立以下共享组件，避免页面重复：

### 5.1 `GuidedPageHeader`

统一显示页面名称、一句话用途、当前状态和一个主要下一步。次要入口使用低权重链接或放入技术详情。

### 5.2 `OnboardingGuide`

显示五步流程和真实状态。未完成用户在 Dashboard 看到完整引导；已完成用户仅看到“基础设置已完成”，并可主动重新打开使用指南。

### 5.3 `GuidedEmptyState`

所有空状态回答：

- 为什么没有数据；
- 用户需要做什么；
- 一个明确按钮。

### 5.4 `ActionFeedback`

统一准备中、处理中、已完成、失败和取消状态。完成时说明实际创建或更新了什么；失败时说明发生了什么、可能原因、解决办法和是否可重试。

### 5.5 `TechnicalDetails`

统一收起模型 ID、协议、Base URL、凭据指纹、内部 ID、原始枚举、JSON Payload、错误码和历史快照。默认关闭，且不影响主要操作。

## 6. 页面改造

### 6.1 Dashboard

- 未完成基础流程时，优先展示首次使用指南而不是大量空图表；
- 只突出当前状态、最重要问题、一个推荐下一步和最近完成；
- 日常用户显示最多四个业务指标、1 至 3 个优先事项和真实最近完成记录；
- 专业评分移动到后续区域或技术详情。

### 6.2 Provider / AI 连接

- 普通用户先区分“官方 AI 平台”和“第三方兼容接口”；
- 协议类型只在自动判断不足时作为高级设置显示；
- 网关卡片默认仅显示名称、连接状态、模型数量、是否可用和主要操作；
- Base URL、协议、密钥版本和错误码进入技术详情；
- `ACCOUNT_BALANCE_INSUFFICIENT` 明确说明 GeoPilot 已连接服务商，但服务商因余额拒绝请求，并提供充值或更换 Key 的解决办法；
- 模型列表显示友好名称、用途和状态，完整模型 ID 收起。

### 6.3 AI 搜索检测

- 支持保存、列出和归档检测问题；
- 无问题时引导添加第一个问题；
- 有问题无结果时突出“运行第一次检测”；
- 有结果时优先显示品牌是否出现、出现次数、主要竞品和优先问题；
- 真实回答与技术字段默认收起；
- 每条结果明确标记官方 API、第三方兼容接口或真实产品验证来源。

### 6.4 GEO Analyzer

- 优先显示总体状态、最重要三个问题、做得好的地方和下一步；
- 使用普通业务语言解释问题、影响和建议；
- 高优先级问题使用“创建修复任务”；
- 技术指标保留在 Tooltip 或详情。

### 6.5 Growth Action 与 Growth Agent

- Action 优先显示任务、原因、负责人、进度与完成标准；
- Agent 优先显示系统计划、当前步骤、已完成内容和是否需要确认；
- 所有状态转换为中英文普通语言；
- 原始枚举和执行证据默认收起。

### 6.6 Automation

- 优先显示任务名称、状态、完成步骤、下一步和结果；
- Run ID、Step ID、JSON 和错误码进入技术详情；
- Before/After 使用真实快照解释变化；无可比数据时明确显示无数据；
- 保留 Dry Run、Safe/Standard/Expert 和人工确认逻辑。

### 6.7 Growth Report

- 列表页优先说明本周期发生了什么和为什么要生成报告；
- 详情页优先显示变化、完成行动、下周期建议和数据来源；
- 复杂快照字段及 HTML 预览后置并默认收起；
- 报告继续只读 `GrowthReport.snapshot`，不重新查询当前业务数据。

### 6.8 Project Settings

- 使用普通语言解释设置对检测的影响；
- 保存后说明更新了哪些信息及下一步；
- 删除项目使用明确文案和确认弹窗。

## 7. 导航与双语

主导航按普通用户频率调整为：

1. 首页；
2. AI 搜索检测；
3. 网站分析；
4. 优化任务；
5. 自动执行；
6. 报告；
7. AI 连接；
8. 项目设置。

现有高级功能不删除，放入分组或高级入口。移动端保留抽屉、遮罩关闭、滑动关闭和路由切换自动关闭。

所有新增文案进入现有 i18n 字典：

- 中文模式使用完整中文，必要技术名称放在 Tooltip；
- 英文模式使用完整英文；
- 不在英文模式中硬编码中文；
- 不在中文主界面混排无法理解的英文枚举。

## 8. 错误处理与安全

- 所有新增 API 使用 Session 和 Project ownership 校验；
- 未登录返回 401，跨用户返回 403；
- 服务端标准化问题文本并验证长度；
- 归档操作不删除 Result、Citation 或历史证据；
- Provider Key 不返回前端、不写日志、不写截图；
- 技术错误码仅在详情中展示；
- 未知错误返回安全通用错误，不返回堆栈或数据库信息。

## 9. 测试与验收

自动测试覆盖：

- Query 保存、标准化、去重、重新激活和归档；
- 保存 Query 不创建 Result；
- 运行复用 Query，并为重复运行新增 Result；
- 旧 Result 不变；
- 失败 Result 无回答、品牌提及和 Citation；
- 五步状态完全从真实数据推导；
- Dashboard 唯一下一步；
- Provider 余额不足提示；
- 空状态、按钮文案、状态翻译与技术详情默认收起；
- 中文无错误混排、英文无中文；
- 危险操作确认与权限隔离。

完成后执行：

- 全部自动测试；
- `npm run lint`；
- `npx tsc --noEmit`；
- `npx prisma validate`；
- `npm run build`。

真实 Chromium 验收覆盖 1440×900、375×812、390×844、430×932，并检查 Dashboard、Provider、Monitoring、Analyzer、Action、Agent、Automation、Report、Settings、语言切换和移动导航。记录 Console、React、Page、Promise、横向滚动、按钮高度、文字溢出及主要下一步。

生产部署后复验 401、200、403、Session Cookie、30 天 Remember Me，以及临时测试数据清理。

## 10. 不在本轮范围

- 不新增 Onboarding 数据表；
- 不重写 Provider、多网关、密钥加密或模型验证架构；
- 不接入新的外部 AI 平台；
- 不新增 CMS 发布、邮件、Webhook 或对象存储；
- 不伪造真实产品验证；
- 不删除旧路由或已有高级功能；
- 不重做品牌视觉系统。
